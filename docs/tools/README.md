# 工具目录与组织约定

Venus Tools 的各工具独立维护需求与业务代码，通过同级目录横向扩展。当前优先梳理的第一个完整工具是“任务提醒”；其他工具文档仍用于记录已有原型，不代表已经排入正式开发。

## 文档与代码布局

沿用仓库已有的文档目录，代码在开始正式实现时按工具归拢：

```text
docs/
  tools/
    README.md                   工具索引和组织约定
    reminders.md                任务提醒的唯一需求入口
    <tool-id>.md                后续工具的独立需求

VenusTools/
  Tools/                        后续实现时创建
    Reminders/
      iOS/                      任务提醒的 iPhone 页面和平台逻辑
      Watch/                    任务提醒的 Watch 页面和平台逻辑
      Shared/                   本工具两端共用的数据和规则
    <ToolName>/                 其他工具按同级目录增加
  Shared/                       应用级主题、基础组件与跨工具公共能力
  iOS/App/                      iPhone 应用入口与工具导航
  Watch/App/                    Watch 应用入口与工具导航
```

以上 `Tools/` 是后续代码归属约定，本次只落需求文档，不创建空业务模块、不搬迁现有 `Views`、`Stores` 或 `Shared` 文件，也不修改 Xcode 工程引用。

## 新增工具时的规则

1. 确定稳定的工具标识，在 `docs/tools/<tool-id>.md` 创建独立需求，并加入上方索引。
2. 文档至少说明目标、属性、页面与流程、缺省和失败状态、iPhone/Watch 范围、通知或同步规则、验收场景、带编号的决策及选择理由；不适用或排除的部分明确标记。
3. 开始开发后，将该工具代码放在 `VenusTools/Tools/<ToolName>/`；按需要创建平台子目录，不为不支持的平台放空壳。
4. 页面与业务规则分开；仅供某个工具使用的数据和逻辑留在工具内部，实际被多个工具使用的能力再提取到公共层。
5. 应用入口负责注册和导航，不集中承载各工具的业务逻辑。新增工具尽量通过新增同级模块完成。
6. 同一功能保留一个正式需求入口；辅助设计、示例或后续拆分文档从该入口链接，避免多份需求互相冲突。
7. 后续优化先修改文档再改行为，记录旧规则、新规则、日期、反馈/测试证据、受影响验收及迁移；保留修订历史，避免无法判断当时为何这样实现。
