## 1. 范围与默认行为

- iPhone 增加独立的“设置”Tab，与各工具同级；它是应用设置入口，不是需要同步到 Watch 的工具。
- 第一项为“模型配置”。允许添加多个配置，每个配置对应一个实际模型及一组接入、生成参数；同一个实际模型可以有多个不同名称、不同参数的配置。
- 支持“本地模型”和“第三方模型”。本地模型分为“iPhone 本机”和“局域网服务”，后者包括用户自己运行的 Ollama、LM Studio，必须提示内容会发送到该设备，不能宣称手机断网仍可用。
- 默认继续采用本机文字、视觉和语音方案。第三方配置由用户自行添加、提供凭据并选择使用，不预置有效密钥、不自动开通服务、不自动切换到云端。
- 首版支持本机 MLX/MLXVLM、WhisperKit，以及 OpenAI Chat Completions 兼容、Anthropic Messages、Gemini generateContent 三种远程调用协议。Ollama/LM Studio 首版使用其 OpenAI 兼容接口；不同时实现它们的原生协议。
- 任务对话和今日总结可分别选择配置。任务图片仍由本机 OCR/视觉模型识别，语音仍本机转写；选择外部文字模型时，只按授权发送必要的转写、识图文字/摘要及任务上下文。本轮不增加任务原始图片或录音外发功能。
- 本文的界面默认值、命名长度和引用规则属于产品设计选择；第 4 节的接口字段依据官方资料。支持某协议不等于支持所有模型、地区、套餐或输入模态。

## 2. 页面与流程

### 2.1 页面层级

```text
设置 Tab
  模型配置（显示已保存配置数量）
    模型列表
      添加模型 → 独立的“添加模型”页面
      点击已有配置 → 独立的“编辑模型”页面
      工具使用模型 → 按工具与功能选择已保存配置
```

- 设置页首个列表项显示“模型配置”、简短说明及配置数量；点击进入模型配置管理页，展示已保存模型列表和始终可见的“添加模型”按钮。
- 无配置时显示说明与“添加第一个模型”，点击进入添加页；已有配置时，添加页保存成功后回到列表并显示新行，可反复添加。
- 列表每行显示配置名称、本机/局域网/第三方类型、提供方、实际模型标识、能力、启用状态、准备或测试状态及被引用的功能数量；不显示完整 API Key。
- 默认按创建时间从早到晚排列；编辑和重命名不改变顺序。不以测试成功替代当前可用性的实时保证。
- 添加和编辑共用表单：基本信息、按类型显示的接入参数、折叠的高级参数、测试操作、保存。切换模型类型或协议时提示将重置不兼容字段，确认后清空这些字段，不把旧密钥带给新服务商。
- 保存前做本机格式校验；允许离线保存格式正确的配置并标为“未测试”或“模型未下载”。保存不自动发起请求、下载权重或改变工具绑定。
- 返回时若有未保存变更，提供“继续编辑 / 放弃修改”；不保存半成品配置。编辑测试不保存表单，失败保留已填内容。

### 2.2 测试与状态

- “测试配置”由用户主动触发，使用当前表单值，发送固定的简短测试文字；语音配置用应用内固定样本。测试不读取真实任务、对话、相册或录音。界面说明外部测试可能产生服务费用。
- 本机模型分别显示未下载、下载中、已下载待验证、加载中、可用和失败；未下载时提供下载入口，不因点击保存而下载。远程配置区分未测试、测试中、测试成功、测试失败和已禁用。
- 必须实际调用所填模型并解析有效响应；能获取模型清单、HTTP 200 或能连通主机都不能单独判为推理测试成功。返回网页、错误 JSON、空结果或格式不兼容应判失败。
- 测试只证明对应能力：文字测试成功不代表已验证图像、结构化输出、工具调用或语音能力。额外能力需官方元数据或针对性样本验证；未验证标注“待验证”。
- 修改模型、地址、凭据、协议或生成参数后，旧测试结果失效；记录最近测试时间、所测配置版本及经过脱敏的结果。仅重命名不必重新测试。
- 测试最多 60 秒，可取消；取消或离开后，迟到结果不修改新表单。工具正式请求的时间上限仍由工具文档决定。

## 3. 配置数据与共同字段

| 字段 | 必填与缺省 | 校验或用途 |
| --- | --- | --- |
| 配置标识 `id` | 保存时生成不可变 UUID | 工具引用的实际键；不使用名称、模型 ID 或列表下标作键 |
| 配置名称 `name` | 必填，去除首尾空白后 1～50 字符，至少含一个汉字 | 全列表按 Unicode 兼容规范化及英文大小写不敏感规则唯一；例如“本机日常整理”“工作总结”；重复时提示改名 |
| 类型 `execution` | 必填，默认 iPhone 本机 | `onDevice` / `lanService` / `thirdParty`；决定网络、参数及隐私说明 |
| 提供方 `provider` 与协议 `adapter` | 必填，按类型选择 | 提供方用于预设与展示；协议用于请求和响应适配，两者分开保存 |
| 模型标识 `modelID` | 必填 | 本机为受支持模型模板的资源标识；远程为服务商模型 ID 或用户部署名，区分大小写，不与配置名称混淆 |
| 能力 `capabilities` | 由模板、官方信息或测试得出 | 文字生成、图像理解、语音转写分别声明；另记录结构化输出、工具调用、流式支持；未知能力不能作为已验证能力展示 |
| 启用 `enabled` | 默认开启 | 禁用后仍在列表保留，工具提示不可用，不自动找其他配置代替 |
| 请求超时 `timeoutSeconds` | 默认 60，允许整数 10～120 秒 | 单次模型子调用上限；实际采用它与工具单次/整轮剩余时限的较小值，不能延长任务整轮时限 |
| 生成参数 `generation` | 可选；默认采用受支持模板/服务商默认值 | 仅展示本协议、所选模型支持的字段；未填则不发送；语音不复用文字采样参数 |
| 凭据引用 `credentialRef` | 有鉴权时必填 | 只保存对安全存储的引用，不在配置普通数据中保存明文密钥 |
| 配置版本与时间 | 自动维护 | `revision`、创建/修改时间；支撑测试失效、请求快照与变更后的授权检查 |

引用示例：两个配置可都使用同一实际模型，一个命名“任务整理”，另一个命名“简短总结”；工具只保存所选 `id`。配置改名后所有选择器显示新名称，无需重新绑定。更换地址或实际模型仍是编辑同一配置，但从下一次请求使用新版本，并按第 5、6 节处理在途请求与外发授权。

## 4. 按模型类型补齐参数

以下官方资料查询于 **2026-10-19**。接口范围、模型 ID 和能力可能调整，正式接入时固定适配器版本并用对应服务实测；不以文档示例代表本项目已经接通。

### 4.1 iPhone 本机模型

| 模型类别 | 必需配置 | 可选或只读信息 |
| --- | --- | --- |
| MLX 文字 | 运行时 `MLXLLM`、受支持模型仓库 ID、固定 revision/提交、资源清单 | 模板控制分词器/对话模板；生成参数可包括 `maxTokens`、`temperature`、`topP`、`repetitionPenalty`；支持项取决于锁定的运行库与模型 |
| MLX 视觉 | 运行时 `MLXVLM`、支持的视觉模型 ID、固定版本、含图像处理器的资源清单 | 必须有图像能力；不能给普通文字权重勾选“支持图片”就当作视觉模型 |
| WhisperKit 语音 | 运行时 `WhisperKit`、多语言模型变体、固定仓库版本与资源清单 | 识别语言默认自动，可选中文；任务固定为转写，不自动翻译；不套用文字模型的生成字段 |

- 首次模型配置初始化时建立“本机文字整理”“本机图片理解”“本机语音转写”三个具名模板，分别沿用 `mlx-community/Qwen3-1.7B-4bit`、`mlx-community/Qwen2-VL-2B-Instruct-4bit`、Whisper 多语言 `small`；初始均显示尚未下载，不能显示为可用。初始化只执行一次，用户删除后不反复补回。
- 首版从已验证模板选择本机资源，可为同一模板新增多个命名参数配置；不承诺任意 Hugging Face 仓库、GGUF 或桌面模型可直接在 iPhone 加载。资源精确 revision、文件大小、校验和、许可证和运行库版本在实现时锁定并展示；此处未完成锁定或设备兼容验证。
- 本机无需 Base URL 和推理 API Key。下载来源若需要访问令牌，使用独立的下载凭据，不将其当作推理密钥。缓存路径由应用管理，用户不填 Windows/Mac 文件路径。
- 下载前展示用途、大小、剩余空间与受影响功能；由用户主动开始，默认 Wi-Fi，蜂窝每次明确继续，支持暂停/继续/重试。相同资源版本共用缓存，配置之间不能互相覆盖参数；权重大小不等于运行内存。
- “删除配置”和“释放模型文件”分开：前者按引用规则处理，后者显示影响的全部配置/能力，仅删除共享权重，保留配置、任务及已保存文本，相关状态回到未下载。

依据：[MLX 模型配置与加载](https://github.com/ml-explore/mlx-swift-lm/blob/main/Libraries/MLXLMCommon/ModelConfiguration.swift)、[MLX 生成参数](https://github.com/ml-explore/mlx-swift-lm/blob/main/Libraries/MLXLMCommon/Evaluate.swift)、[WhisperKit 官方用法](https://github.com/argmaxinc/argmax-oss-swift)。既有模型选型理由与 iPhone 16 验收边界见 [共用 AI 需求](tools/ai-assistant.md)。

### 4.2 局域网本地服务

- 必填提供方、OpenAI 兼容协议、Base URL 和服务上已安装/加载的模型 ID；鉴权方式选择“无 / Bearer Key”，默认无，启用鉴权或网关后必须填写密钥。
- 地址示意：Ollama 为 `http://<电脑局域网地址>:11434/v1`，LM Studio 为 `http://<电脑局域网地址>:1234/v1`；端口可修改。`localhost` / `127.0.0.1` 在 iPhone 上指手机自身，不能直接代表用户电脑。
- 需要服务端开放局域网访问、设备可达及 iOS 本地网络授权。首次主动连接时再请求系统权限；拒绝后保留配置和手动工具功能，并显示开启指引。不自动扫描网络或替用户修改服务器、防火墙。
- 局域网服务使用第 4.3 节的兼容接口参数；本机下载按钮不用于管理电脑上的权重。Ollama/LM Studio 的原生参数不直接混入兼容请求。
- “局域网服务”指该设备实际运行本地权重。Ollama 也可经本地服务调用云端模型，私网地址本身不能证明推理只在局域网；使用云端模型或转发网关时按第三方处理并说明实际目标，不以“本地服务”掩盖云端处理。
- 只允许将可达的私网地址或解析为私网地址的本地域名标为局域网；公网部署按第三方处理。局域网 HTTP 需明确显示明文传输提示；含真实密钥时要求 HTTPS。ATS 仅配置所需本地网络例外，不全局关闭安全连接校验。

依据：[Ollama OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)、[LM Studio OpenAI 兼容接口](https://lmstudio.ai/docs/developer/openai-compat)。

### 4.3 第三方模型与协议差异

远程共同必填项为提供方、协议、Base URL、模型 ID、所选鉴权所需凭据。默认提供可编辑的官方地址预设，用户可填写受信任的兼容服务；不把密钥写进 URL。Base URL 保存 API 根路径，适配器追加下面的操作路径一次；若粘贴完整操作地址，提示改为根路径，避免重复 `/v1` 或 `/chat/completions`。

| 协议 | 地址与鉴权 | 请求必需内容与可选字段 |
| --- | --- | --- |
| OpenAI Chat Completions | 官方根地址 `https://api.openai.com/v1`；追加 `/chat/completions`；`Authorization: Bearer <key>` | 请求需 `model`、`messages`；可选 `temperature`、`top_p`、`stream`、`response_format`；输出上限由模板在 `max_completion_tokens` / `max_tokens` 中选择一个，不能同时发或当作通用别名 |
| Anthropic Messages | `https://api.anthropic.com/v1`；追加 `/messages`；`x-api-key` 与必需的 `anthropic-version`（官方示例为 `2023-06-01`） | 请求需 `model`、`messages`、`max_tokens`；`system` 是顶层字段；可选 `temperature`、`top_p`、`stop_sequences`、`stream`，并按所选模型限制显示 |
| Gemini generateContent | `https://generativelanguage.googleapis.com/v1beta`；追加 `/models/{modelID}:generateContent`；`x-goog-api-key` | `modelID` 在路径，消息为 `contents`；可选 `systemInstruction`；生成字段位于 `generationConfig`，包括 `temperature`、`topP`、`maxOutputTokens`、`stopSequences`；流式另用 `:streamGenerateContent?alt=sse` |

这些协议分别依据 [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini generateContent](https://ai.google.dev/api/generate-content) 和 [Gemini API Key](https://ai.google.dev/gemini-api/docs/api-key)。应用负责构造消息和系统指令，不让用户手填 `messages`、`contents` 等每轮请求体。

| 提供方预设 | Base URL / 额外配置 | 兼容注意事项 |
| --- | --- | --- |
| DeepSeek | 官方预设 `https://api.deepseek.com`，Bearer Key，选择 OpenAI 兼容协议 | 模型 ID 按服务商当前清单填写；输出上限使用其 `max_tokens`；思考开关和强度按该模型的 `thinking` / `reasoning_effort` 支持情况设置，不沿用其他提供方枚举 |
| 阿里云百炼 / 千问 | 使用用户地域与业务空间对应的 `/compatible-mode/v1` 根地址，Bearer Key | 地域、业务空间地址与 API Key 对应；从控制台复制完整根地址，不只填模型名称；不把某地域地址套到所有账号 |
| 其他兼容服务 | 用户填写 HTTPS 根地址、模型 ID、鉴权信息 | 仅承诺已测试的 Chat Completions 子集；不能因为宣称兼容就默认支持视觉、JSON Schema、流式用量或函数调用 |

预设依据：[DeepSeek 首次调用](https://api-docs.deepseek.com/zh-cn/)、[DeepSeek 参数](https://api-docs.deepseek.com/api/create-chat-completion/)、[百炼兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)。具体模型 ID 允许手填，并在服务支持时提供用户主动触发的模型列表；模型列表失败不阻止保存，列表成功不替代调用测试。

### 4.4 高级参数与校验

- 温度、Top-p、输出 token 上限、停止序列、流式和思考选项都按“协议 + 模型”显示、校验和映射；默认高级参数留空，使用受支持模板或提供方默认值。各家范围不统一，不设置一份全局有效的温度/上下文上限。
- 当前 Anthropic 文档已将新模型的温度与 Top-p 自定义标记为不支持/弃用，不能仍统一展示为可调参数；OpenAI 的 `max_completion_tokens` 包含可见输出及推理 token，不能把它等同于纯正文长度。以对应官方模型说明确定字段与预算。
- 输出上限填写正整数，不超过已知模型限制；上下文窗口为模型信息，不是用户填大就能扩容。输入加输出预算超过已知限制时提示缩短内容，不静默截掉用户材料。
- Anthropic 的 `max_tokens` 必须有值，表单初始建议 1,024，并按具体模型校验。OpenAI 兼容模板必须明确 token 字段；不支持的温度、停止词或结构化输出不发送。未识别的自定义模型须先选择兼容参数模板并标记待验证。
- Anthropic API 版本由适配器预设为经验证的版本，保留在配置中；Gemini 的 `v1beta` 属于根路径版本，不混作模型 ID。版本变化需重新测试。
- 高级自定义请求头仅在所选网关确有需要时填写；敏感值进入安全存储。不能覆盖应用管理的鉴权、Host、Content-Type，不能以任意 JSON 覆盖模型、消息、上传内容或工具安全规则。首版不提供任意请求脚本。
- 结构化输出用于增强可靠性；不支持时可走文字结果解析与应用校验，不能把“能输出 JSON”当作具有执行应用操作权限。任务保存、字段验证与草稿冲突规则保持不变。
- 首版不建设 Azure 部署专用协议、OAuth、任意远程语音接口或厂商全部原生参数；这些需要独立适配和验收，不能标记为已经支持。

## 5. 其他工具如何引用

### 5.1 按工具功能绑定

- “工具使用模型”按工具列出可配置功能，选择器直接显示模型配置名称及本机/局域网/第三方标记。候选来自同一个注册表，不在工具内再填写地址或密钥。
- 每个绑定保存稳定的 `toolID`、`purpose`、`modelConfigurationID`。一个配置可被多个功能共用，一个工具不同功能可选不同配置。
- 只列出已启用且能力匹配的配置；未测试显示提示，用户可明确选择后尝试，不把未验证能力标成可用。禁用、密钥缺失、资源未下载或配置已删除时说明原因并提供管理入口。

| 工具功能 | 首次默认与继承规则 | 实际输入边界 |
| --- | --- | --- |
| 任务提醒 · AI 对话 | 首次绑定“本机文字整理”，之后记住独立选择 | 当前输入、必要对话和最新任务草稿；语音先本机转写，图片先本机识别；选择外部文字配置时告知转写/OCR/场景摘要也会外发 |
| 任务提醒 · 今日总结 | 首次绑定同一个本机文字配置，但与对话独立保存，不随对话改选 | 按任务文档筛选的标题、概要与必要结构化属性；遵守前 30 项概述和完整本机清单规则 |
| 任务提醒 · 智能查找 | 首版沿用对话配置，显示“跟随 AI 对话”，不另增必选项 | 仅发送本次自然语言查询与必要日期/时区来解析条件；全量任务检索、计数和过滤仍在本机，不能上传整库 |
| 共用图片理解 / 语音转写 | 首版引用本机视觉 / 本机语音模板，不能被文字配置覆盖 | 原始图片和录音仅在 iPhone 处理；OCR 使用系统 Vision，不假装需要独立大模型配置 |
| 后续工具 | 在工具文档声明功能、能力要求、输入和缺省，再注册绑定 | 复用同一套配置服务，不复制密钥或自行绕过外发授权 |

默认绑定只在初次初始化创建；默认配置被删除后显示未配置，不在启动时悄悄重建或改用列表第一项。相同外部配置用于两个功能时，仍分别明确其外发材料和授权范围。

### 5.2 编辑、禁用、删除与请求一致性

- 改名不影响绑定；普通参数编辑从下一次请求生效。同一配置被多处引用时，编辑页说明影响范围；测试使用编辑草稿，正式调用仍使用已保存版本。
- 请求启动时固定配置 ID、版本与绑定，并遵守工具草稿修订保护。配置或绑定发生影响调用的变化、被禁用/删除、授权撤回时，取消相关在途请求并丢弃迟到结果；仅改名不取消。不得在一轮内换地址、重试到另一服务或采用新密钥继续旧请求。
- 删除配置前显示引用它的工具与功能；有引用时须先选择兼容的替代配置，或明确解除这些绑定，统一保存后才删除。取消删除不改变任何绑定，不能只按名称查找影响范围。
- 禁用后保留原引用并标明不可用，相关 AI 功能可重新选模型或手动继续。鉴权失败、额度不足、断网和本机模型缺失均不能触发隐式跨配置回退。
- 删除配置时清理专属凭据，不能误删其他配置仍使用的凭据或共享权重；释放本机权重按第 4.1 节单独操作。任务、已保存文本、通知和 Watch 数据不因配置变更而删除。

## 6. 数据、网络与隐私

- 普通配置与工具绑定仅保存在 iPhone；不向 Watch 同步服务地址、密钥或模型文件，不新增账号和业务云同步。
- API Key、下载令牌及敏感请求头使用 iOS Keychain，默认遮蔽且不自动复制；凭据不可用时提示重新填写，不显示为已鉴权。不进入 UserDefaults、普通 JSON、草稿、崩溃日志或版本库；不提供密钥导出。本次用户提供的博查测试凭据支持第 11 节限定的私人加密初始化导入。
- 第三方地址必须为 HTTPS，不包含用户名密码、查询密钥或片段；不跳过证书验证。局域网 HTTP 例外见第 4.2 节。跨主机重定向不转发鉴权或用户内容，应停止并提示核对地址。
- 保存配置、打开列表、改名和普通任务编辑均不自动调用模型；任务今日总结仍沿用其打开弹层自动生成一次的规则，但外发授权尚未完成时先等待用户明确继续。
- 第一次为某工具功能选用离机配置时，明确展示配置名称、目标主机、可能发送的数据类别及费用由服务方决定；在首次实际外发前取得该功能的明确授权，可记住并撤回。连接测试只授权测试材料，不授权真实任务外发。
- 目标主机、根路径、模型、协议或输入类别改变，或功能改绑外部配置时，必须重新确认外发范围；改名无需重复授权。授权撤回后停止后续外发，不承诺撤回服务商已收到的内容。
- 默认本机模式无需外部推理请求，权重缓存且输入材料在本机时支持断网；局域网需能访问服务器，第三方需能访问对应服务。不能将本机故障、无网或性能不达标当作自动启用第三方的理由。
- 原始任务录音、图片和草稿的本机保留仍按任务文档执行。服务商的数据保留与训练政策需在其说明中查看，应用不能承诺外部服务不留存或替用户删除远端副本；本机“删除配置”只清理应用内配置与专属凭据。

## 7. 失败处理

| 情况 | 应用行为 |
| --- | --- |
| 必填缺失、重名、URL/数字非法 | 在相应字段说明原因，不保存，不清空其他字段 |
| 本机不支持、未下载、空间/内存不足 | 显示具体准备状态，提供受支持模板、下载/清理/重试或手动操作；不自动下载或改走云端 |
| 局域网权限拒绝或不可达 | 说明权限/地址/端口检查入口，保留配置；不误报模型不存在 |
| 401 / 403 | 提示凭据无效或权限不足，不显示密钥，不自动反复重试 |
| 模型不存在 / 不支持参数或模态 | 提示核对模型 ID、协议、能力与高级参数；保留输入，不声称只要换 Key 即可解决 |
| 429、额度不足、5xx | 区分限流、余额和服务暂不可用；展示脱敏原因，允许用户重试，不自动切换配置或无限重试 |
| 超时、取消、响应截断/格式不合法 | 保留任务输入与草稿；截断结果不作为成功提交属性，迟到或失效结果不写回 |
| 配置/凭据存储失败 | 保留正在编辑的表单并说明保存失败；不把半写入的配置加入列表或破坏既有配置 |

## 8. 架构与后续实现边界

- 设置页面只展示表单、状态和校验结果；由公共模型注册表管理配置与稳定标识，由凭据服务管理 Keychain，由绑定服务解析工具用途，由独立适配器执行本机或远程请求。
- 文字归纳、语音转写与图片理解继续使用已有服务接口方向。工具传入用途与所需能力，公共服务解析配置、验证授权、执行请求并返回统一结果；工具保留数据筛选、草稿合并、结构校验与保存职责。
- 代码归属 `VenusTools/iOS/Settings/`（设置页面）和 `VenusTools/iOS/AI/`（iPhone 公共服务），不把密钥放进跨平台 `Shared` 或 Watch 目标。
- 正式实现时采用带 schema 版本的配置持久化；初次从硬编码模型迁移为具名配置和 UUID 引用，幂等创建默认项，不虚构已下载/测试成功状态。写入完整成功后切换版本，失败保留旧数据；不改变任务 ID、通知安排或 Watch 完成状态。
- 后续新增设置项继续在本文维护；协议、默认模型、外发内容、引用或删除规则变化时，先记录旧规则、新规则、原因、受影响验收与迁移方案，再改变行为。

| ST-08 | 分别接入兼容、Anthropic、Gemini 及不同生成参数的模型 | 地址只拼接一次，鉴权和消息/输出上限字段符合各协议；不支持的参数不会混发；真实服务验证需使用测试凭据 |
| ST-09 | 任务对话与今日总结分别绑定，重命名配置，再改选对话配置 | 各功能按 UUID 使用所选配置；改名不失效，总结不被对话改选覆盖；智能查找明确跟随对话配置 |

| ST-11 | 删除被多个功能引用的配置，取消后再选择替代/解除绑定 | 先显示影响范围；取消不改引用，替代/解绑与删除一致保存；任务和其他配置不被删除 |
| ST-12 | 请求期间改绑、禁用、改地址或撤回授权；另测只改名 | 影响调用的变化取消旧请求且丢弃迟到结果；新请求使用已保存新版本；仅改名保持稳定引用 |
| ST-13 | 首次外部测试、任务外发、改地址/模型，再撤回授权 | 测试不读取真实任务；每个功能按实际材料授权，变化后重新确认；未授权和撤回后无后续外发 |
| ST-14 | 任务输入语音/图片后使用外部文字模型，并执行智能查找和今日总结 | 原始录音/图片留在手机；已告知必要转写/识图摘要外发；查找不传任务整库，总结按固定筛选/上限，保存规则不变 |
| ST-15 | 检查普通配置、日志、备份导出入口与 Watch 同步数据 | 不含明文密钥；首版无含密钥导出；Watch 无配置和凭据；恢复时凭据缺失明确提示 |
| ST-16 | 超时、限流、余额不足、配置写入中断或模型输出截断 | 错误可恢复，输入不丢；不隐式换服务、不提交截断属性、不留下可被引用的半配置 |

## 10. 本轮变更与关联文档

- **旧规则：** 应用与共用 AI 需求仅允许本机推理；任务提醒已声明可配置对话/总结模型，但没有对应设置文档。

## 11. 2026-10-22 实现决策与交付边界

第 10 节保留需求建立时的历史记录。本节记录此次实现；前文是目标基线，不能用编译成功替代全部 ST 场景的真机验收。

- 设置为独立第五个 Tab，含模型列表、共用添加/编辑页面、删除引用处理和工具绑定。配置用 UUID，名称必须含中文；任务对话、总结独立绑定，查找跟随对话，三种用途分别确认外发。绑定键带 `reminders` 工具命名空间，后续工具需增加独立用途，不能复用任务授权。
- 首次创建三个本机模板和“博查深度求索测试”。默认对话与总结仍用本机 Qwen3，不自动绑定博查，不预置有效密钥。博查为第三方兼容网关，根路径 `https://api.bocha.cn/v1`，实际标识 `deepseek-v4-flash`；不将其标成 DeepSeek 官方直连。
- 用户明确要求提前加入私人测试 Key，因此新增限定的 `.venusmodel` 加密初始化导入。一次性文件和随机高熵口令在仓库外单独保存；AES-256-GCM 加密，SHA-256 从随机口令派生密钥。用户在手机 Files 选择文件并输入口令后写入 Keychain，导入不改工具绑定和授权。它不是通用备份/密钥导出功能，不接受明文 Key JSON，也不把文件放进 IPA。随机口令需独立传递，不能使用短口令替代。
- 普通配置存于带 schema 的 iPhone Application Support JSON，凭据及敏感自定义请求头仅存 Keychain，使用 `WhenUnlockedThisDeviceOnly`。改配置先写入新凭据，再原子写配置，失败回滚新凭据；成功后才清理旧专属凭据。损坏/未知版本原文件保留并停止写入。
- 测试用当前表单、固定文字，不使用任务；只有有效非空模型正文才成功。测试不保存，保存后才更新正式配置。变更地址、协议、模型、凭据、生成参数或启用状态使旧测试与授权失效，仅改名保持有效。切换类型、协议和接入预设均确认后清空不兼容字段及凭据。
- 本轮三种远程适配器只声明文字输入。停止序列最多四项；自定义模型采用待验证协议模板，用户填写参数须符合提供方限制。Anthropic 不展示温度和 Top-p，缺省输出上限 1,024；兼容协议输出上限字段二选一。流式协议会校验完整终止后一次性返回正文，目前不逐字更新界面。不开放任意脚本、JSON 请求体或厂商思考参数。
- 为避免后台旧结果误用，任何影响调用的配置、绑定、授权变更会保守地取消所有当前文字请求，并校验返回前配置快照；仅改名、测试记录不取消。失败不自动重试或跨配置回退。任务原有字段校验、合并和保存规则继续生效。
- 第三方只允许 HTTPS；局域网只接受私网地址/本地域名，域名请求前核验解析；真实 Key 或敏感头禁止 HTTP。ATS 仅加本地网络例外，保留 TLS 校验；所有重定向停止。局域网权限拒绝提示检查系统本地网络权限，不改服务器或防火墙。
- Qwen3 沿用锁定权重和 MLX 运行库，多个配置共享资源，支持独立生成参数；资源下载/导入仍由用户主动操作。Qwen2-VL 与 WhisperKit 尚未接入，模板明确禁用、不能被文字功能选择。系统离线语音与明确的 OCR 模式继续可用；本轮不宣称完整实现视觉/WhisperKit 或通过 ST-06 的三种本机模型验收。
- 博查已于本次开发使用用户提供的 Key 做固定文字推理，HTTP 200、结束原因 stop、正文“连接成功”；没有发送真实任务。Anthropic/Gemini 目前通过协议构造和解析测试，未用真实账户调用。手机设置交互、Keychain、局域网服务及本机 MLX 推理仍需真机验收。
